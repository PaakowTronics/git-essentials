# Git Essentials — Documentation Missions

## Purpose

These missions train one of the most important skills in the course:

> **How to learn and troubleshoot software without needing someone to hand you the command.**

The learner must use official documentation wherever possible.

The instructor should not provide the final command unless the mission explicitly allows it.

---

# Mission Rules

For every mission:

```text
1. Identify
2. Find official documentation
3. Read
4. Check your environment
5. Predict
6. Execute
7. Verify
8. Record what happened
```

The learner should record:

- the official documentation source;
- the relevant section;
- the operating system;
- the command or procedure used;
- what they expected;
- what actually happened;
- how they verified success;
- any error encountered;
- how they investigated it.

---

# Mission 01 — Identify Your Environment

Before installing anything, determine:

- operating system;
- operating-system version;
- terminal being used;
- CPU architecture where relevant.

### Deliverable

Create:

```text
environment-notes.txt
```

Include:

```text
Operating system:
Version:
Terminal:
Architecture:
```

### Goal

Do not install anything yet.

The skill being tested is:

> **Know your environment before following installation instructions.**

---

# Mission 02 — Find the Official Git Documentation

Find the official Git website.

Start from a search engine if necessary, but verify the domain.

The learner should identify:

- official Git website;
- installation page;
- documentation page.

### Questions

1. What is the official domain?
2. Which page contains installation information?
3. Which instructions apply to your operating system?
4. How would you verify that Git is already installed?

---

# Mission 03 — Install or Verify Git

Use the official Git installation documentation.

Do not receive the installation command from the instructor.

### Requirements

- follow the appropriate instructions;
- do not blindly copy commands;
- verify installation.

### Verification

Use the official or standard verification method and record the result.

### Deliverable

Write:

```text
What I expected:
What I did:
What happened:
How I verified it:
```

---

# Mission 04 — Investigate a Deliberate Error

The instructor provides a command that is intentionally unsuitable for the learner's environment.

The learner must **not** simply try random alternatives.

They must:

1. read the error;
2. identify what it is complaining about;
3. return to official documentation;
4. find the correct environment-specific instructions;
5. explain the difference.

### Goal

Learn that an error is information.

---

# Mission 05 — Install Docker From Official Documentation

Find the official Docker documentation.

Determine:

- the correct installation path for your operating system;
- prerequisites;
- whether a package manager is used;
- how Docker is verified after installation.

### Rule

Do not use a random “one command install” tutorial as the primary source.

### Deliverable

A short installation report.

---

# Mission 06 — Verify Docker

After installation, verify:

- Docker is available;
- the Docker client responds;
- the installation is usable.

If the verification fails:

> Do not reinstall immediately.

Read the error and investigate.

---

# Mission 07 — Clone an Unfamiliar GitHub Project

Find a small public GitHub repository that you have never used before.

Before running `git clone`:

1. inspect its README;
2. identify what the project is;
3. identify requirements;
4. identify setup instructions;
5. identify how the project is run or tested.

Then clone it.

### Deliverable

Answer:

```text
What is this project?
What software does it require?
What does the README tell me to do?
What did I have to install?
How did I verify the setup?
```

---

# Mission 08 — Documentation Conflict

Find two instructions for the same task:

- one official;
- one community/tutorial source.

Compare them.

Do not assume the community source is wrong.

Instead record:

- publication/update information if available;
- versions mentioned;
- operating systems;
- differences in commands;
- whether the official documentation explains the difference.

### Goal

Learn to evaluate instructions rather than blindly choosing one.

---

# Mission 09 — Search an Exact Error

The instructor provides an error message.

The learner must search using:

```text
"exact error message"
```

plus relevant software and environment information.

### Deliverable

Record:

1. exact error;
2. search query;
3. official documentation found;
4. relevant explanation;
5. attempted fix;
6. verification result.

---

# Mission 10 — Read Before Running

The instructor provides a potentially destructive command from official documentation.

The learner must **not run it immediately**.

First answer:

- What does it do?
- What files or settings could it affect?
- Why is it needed?
- Is there a safer preview or verification method?
- What should be backed up first?

Only then may it be executed in a disposable practice environment if appropriate.

---

# Mission 11 — Version Difference

Find documentation for a tool that has multiple versions.

Identify:

- current version;
- version-specific instructions;
- one change between versions.

### Goal

Understand why copying an old tutorial can fail.

---

# Mission 12 — Final Documentation Mission

Choose a tool you have never installed before.

Do everything independently:

```text
Find official documentation
        ↓
Identify environment
        ↓
Read requirements
        ↓
Install
        ↓
Verify
        ↓
Troubleshoot if necessary
        ↓
Document the process
```

The instructor should not provide commands.

---

# Documentation Mission Completion Standard

The learner has mastered this skill when they can say:

> “I don't know how to do this yet, but I know how to find out.”

That is the intended outcome.
